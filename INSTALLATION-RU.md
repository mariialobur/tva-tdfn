# Установка версии 11.1

## Что загрузить

Распакуйте архив и замените содержимое корня репозитория файлами из пакета. ZIP как отдельный файл сайта загружать не нужно.

Основные файлы приложения:

- `index.html`
- `styles.css`
- `data.js`
- `logic.js`
- `store.js`
- `components.js`
- `transition.js`
- `app.js`
- `.nojekyll`

Папки `.github` и `tests`, а также `package.json` лучше также загрузить: они позволяют GitHub Actions проверять проект после изменений.

## После публикации

1. Дождитесь зелёного статуса GitHub Actions / Pages.
2. Откройте сайт в приватном окне либо выполните принудительное обновление (`Ctrl+Shift+R`). Версия 11 использует новый cache-busting для CSS и JS.
3. Убедитесь, что новый пользователь начинает с `#cas-J` — проверки admissibilité.
4. Проверьте последовательность модулей: **Parcours essentiel → Parcours avancé → Atelier autonome**.
5. Откройте `#cas-D` и проверьте пояснение среднего taux 2,92 %: это результат, а не TDFN для применения.
6. Откройте `#cas-N`: сначала должна проверяться допустимость option под TDFN (исключение art. 21 al. 2 ch. 26 LTVA), а уже затем ch. 205/230.
7. Откройте `#cas-M`: кейс должен требовать сначала квалифицировать reprise по art. 83 OTVA без произвольного ch. 415.
8. Откройте `#cas-P`: это продолжение M; документированная charge fiscale вводится в ch. 415 отрицательным значением и увеличивает ch. 500.
9. На мобильном экране проверьте `#cas-D3`, `#cas-L5`, длинные таблицы и диалоги.
8. Проверьте экспорт прогресса и обратный импорт JSON.

- `#cas-D`

- `#cas-I`
- `#cas-P`
- `#cas-K2`

- `#cas-R`
- `#cas-Q`

На первом кейсе «Предыдущий» должен быть отключён; на последнем — «Следующий».

## Старые patch-файлы

Если в репозитории ещё остались прежние файлы `v7-*`, `v8*-learning-path.*`, `ui-fixes.*`, их можно удалить: версия 11 их не подключает.
